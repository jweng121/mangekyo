# Visual audit development demo

## Phase 2: real browser observation

The default page at `http://localhost:3000` is an escalation-first investigation of a **real Playwright-controlled Chromium session** against **synthetic** Harbor Trust ERP data. The ERP is co-hosted at `/erp`; it is not a second service. The older Phase 1 synthetic workflow remains at `/?mode=synthetic`.

### Setup

1. From the repository root, run `pnpm install` (or `pnpm.cmd install` in PowerShell) and `pnpm --filter @mangekyo/visual-audit-dev exec playwright install chromium`.
2. Run `pnpm --filter @mangekyo/visual-audit-dev dev -- --port 3000`. Open `http://localhost:3000`. The browser agent uses that app's `/erp` route.
3. Select **Start monitored agent**. The server launches Chromium, reads bank line 1042, invoice INV-88, and the searched customer record, then prepares a draft allocation. The deterministic invoice-first rule proposes Client A while code B-204 belongs to Client B. The run escalates.
4. Select **Investigate** or a graph checkpoint. The inspector shows an actual screenshot, DOM-derived normalized region, extracted value, tool call and response, agent-provided justification when present, and source evidence. **Zoom to evidence** crops the screenshot view; **Open original capture** retains the full image. No region is drawn when Playwright has no reliable bounding box.
5. Ask about the reads, disagreement, changed field, or branch comparison. The local audit adapter answers from saved snapshots and stores both chat messages. Citation buttons navigate to captured evidence. **Explain Issue** or **Explain Aloud** navigates four cited segments while browser speech plays; written segment buttons work without audio. Pause, Resume, Stop, and Replay are available.
6. Select **Steer Agent** at the escalated proposal. The corrective instruction and source evidence are recorded as a versioned steering request. The server starts a fresh Chromium session from the affected task. The new branch has new screenshots and a separate run ID. Only a draft ERP proposal is made; there is no ledger posting or payment replay.
7. Compare branches, edit the generated report, then move it through **Draft → Pending Review → Approved → Filed**. Only after filing can you **Save Lesson to Memory**. That creates a pending scoped lesson; **Authorize memory** is a separate action. **Run agent with approved memory** starts another browser session and records the memory ID on its snapshots.

The optional smoke test requires a running app: `node apps/visual-audit-dev/scripts/smoke.mjs`. It runs the escalated, steered, and memory-guided agents; checks real PNG artifacts and recorded regions; and exercises report filing and separate memory approval. It adds synthetic local records.

### Dependencies and configuration

Phase 2 adds `playwright` to `@mangekyo/visual-audit-dev` and `convex` at the workspace root; Chromium is installed separately with the command above. The visual-audit package now declares its existing shared contracts dependency and `tsx` for tests. Next.js, React, TypeScript, and the existing graph and inspector remain in place. The graph is the repository's existing React/SVG implementation, not XYFlow. No PDF evidence is used, so PDF.js is not installed. Playwright is used for navigation, locators, DOM bounds, and screenshots; there is no custom CDP driver.

Copy `.env.example` into `apps/visual-audit-dev/.env.local` only when overriding defaults. `MANGEKYO_BROWSER_HEADLESS=false` makes the monitored Chromium window visible. `MANGEKYO_DEMO_TENANT_ID` scopes the local store to a server-selected tenant. The default store is `<OS temp>/mangekyo-local-demo`, outside the Next.js development file watcher. `MANGEKYO_LOCAL_DATA_DIR` can point to another directory outside the watched project. The store uses one JSON document for structured records and an `artifacts/` directory for PNG binaries. Execution events and snapshots append; reports and memory preserve versions. The artifact route checks that the requested ID belongs to a saved snapshot for the configured tenant. This local adapter is a development repository, not a production financial audit store.

`MANGEKYO_LLM_PROVIDER=local` uses the deterministic evidence adapter and needs no key. For Claude audit reasoning, set `MANGEKYO_LLM_PROVIDER=anthropic`, `MANGEKYO_LLM_MODEL` to a Claude model ID available to your Anthropic account, and server-only `ANTHROPIC_API_KEY` in `apps/visual-audit-dev/.env.local`. This uses Anthropic's Messages API with the selected PNG screenshot and a bounded summary of saved observations. The model is instructed to separate recorded facts, agent-provided explanations, its own interpretation, and missing evidence; citation buttons link to saved snapshot IDs. The monitored browser task agent remains deterministic. OpenAI remains an optional alternative with `MANGEKYO_LLM_PROVIDER=openai`, `MANGEKYO_LLM_MODEL`, and `OPENAI_API_KEY`. Missing credentials produce a clear server error. Neither cloud provider was called during local verification. The Claude request follows the [official vision guide](https://docs.claude.com/en/docs/build-with-claude/vision) and [Messages API](https://docs.claude.com/en/api/messages).

`MANGEKYO_TTS_PROVIDER=browser` uses key-free SpeechSynthesis. For Fish Audio, set `MANGEKYO_TTS_PROVIDER=fish` and server-only `FISH_API_KEY` in `apps/visual-audit-dev/.env.local`. The default model is explicitly `s2.1-pro-free`; `MANGEKYO_TTS_MODEL` may select another supported model, including paid ones. `MANGEKYO_TTS_VOICE` is an optional Fish reference ID. The server returns MP3 for the same segment-level evidence navigation, and the key never reaches the browser. Fish Audio lists the free model at $0 subject to fair use, with no SLA; its policy and price may change. Audio text sent to Fish Audio may be retained for model improvement, so review its privacy terms before using real financial data. The web site's consumer free plan has separate limits. This cloud path was not tested with a live key. See Fish Audio's [API pricing](https://docs.fish.audio/developer-guide/models-pricing/pricing-and-rate-limits) and [TTS request format](https://docs.fish.audio/api-reference/endpoint/openapi-v1/text-to-speech). The earlier ElevenLabs adapter remains available with `MANGEKYO_TTS_PROVIDER=elevenlabs`, `MANGEKYO_TTS_VOICE`, and `ELEVENLABS_API_KEY`.

### Finance and persistence boundaries

The ERP form only creates a browser-local draft proposal. `MANGEKYO_FINANCE_ADAPTER=mock` is the only active setting; no finance gateway call or financial transaction occurs. `MANGEKYO_FINANCE_API_URL` and `MANGEKYO_FINANCE_API_KEY` are reserved for a separate authorized adapter. Such an adapter should submit a proposal and receive a gateway decision; steering must never replay a posting. Edwin's finance-core files are untouched.

An optional Convex adapter is implemented in `convex/schema.ts`, `convex/investigations.ts`, and `apps/visual-audit-dev/lib/convex-store.ts`. To use it, configure an OIDC issuer and audience in the Convex deployment, deploy the schema/functions with the Convex CLI, then set `NEXT_PUBLIC_VISUAL_AUDIT_MODE=convex`, `NEXT_PUBLIC_CONVEX_URL`, and server-only `MANGEKYO_CONVEX_AUTH_TOKEN` to a valid JWT for that deployment before building the Next.js app. The issuer/audience in `convex/auth.config.ts` must match the token. The server adapter derives tenant scope from Convex's verified `tokenIdentifier`, ignoring client-supplied tenant IDs. It stores structured records in separate tables and PNGs in Convex File Storage; the Next.js artifact route proxies authorized files. This cloud path is typechecked but **not deployed or live-tested** because no credentials were configured. The supplied server JWT represents one service identity, so production multi-user review still requires a reviewer authentication integration and scoped token issuance. The investigation UI receives server-sent record updates: the Convex adapter subscribes to the authenticated query, while the local adapter polls its development store. The local JSON adapter supports saved investigations after a run finishes but has no multi-user authentication. The optional Claude, OpenAI, Fish Audio, and ElevenLabs paths also need credentials to verify against live services. Convex upload and access behavior follows its [file upload](https://docs.convex.dev/file-storage/upload-files), [file access](https://docs.convex.dev/file-storage/serve-files), and [function authentication](https://docs.convex.dev/auth/functions-auth) documentation.

### Phase 1 synthetic workflow

From the repository root, run `pnpm install`, then `pnpm dev`. Open `http://localhost:3000/?mode=synthetic`.

1. Select **Start synthetic workflow**. Seven checkpoints arrive incrementally. Toggle Execution and Workflow views; select nodes to inspect the structured observations.
2. Select the ownership escalation. The maker proposal and conflicting source evidence open. Select **Explain Issue** to load a four-checkpoint investigation. Browser speech synthesis narrates each segment while the graph and inspector follow its recorded source field. Use Pause, Resume, Stop, or Replay. The written segments and clickable evidence work without audio.
3. Select **Steer Agent from checkpoint**. Review the prefilled correction, submit it, and inspect the new branch and comparison.
4. Select **Save Lesson to Memory**. Edit, approve, or reject the scoped proposal. Revisions create a new version and retain the superseded record.
5. Select **Start second synthetic run**. Its matching maker retrieves approved guidance and requests more evidence before allocation. Select those nodes to see the memory ID and resulting behavior.

This Phase 1 route remains a deterministic synthetic example. Its events do not use the Phase 2 browser capture or persistent investigation store.

The narration provider uses the browser's built-in speech synthesis and requires no credentials. Synthetic highlights reference stored field IDs. The inspector supports recorded text quotes and normalized screenshot rectangles for later integrations; it will not draw a location when that evidence is missing or invalid.
