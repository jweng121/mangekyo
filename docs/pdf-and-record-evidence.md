# PDF and record evidence

The local demo now mixes actual PDF text reads, SQLite SELECT results, a saved INSERT, and a corrected UPDATE. These are real operations against fictional local data, not a production ERP connection.

## Run locally

From `apps/visual-audit-dev`:

```powershell
python -m pip install -r scripts/requirements-evidence.txt
pnpm dev
```

Optional `MANGEKYO_PYTHON` selects a Python executable. Keep `NEXT_PUBLIC_VISUAL_AUDIT_MODE=local` for PDF source storage. Use the app's new-run action, or POST `/api/visual-audit` with `{"action":"start","title":"PDF + database / Trust allocation"}`. Existing historical runs are preserved.

## Evidence types

- PDF: original bytes, SHA-256, filename, page number/count, extracted text, rendered page, and text-coordinate highlights. The original PDF is available from the snapshot. No HTML screenshot substitutes for the PDF.
- Read: source system, resource, operation/status, filters, returned rows, row count, timestamp and truncation indicator.
- Insert: the confirmed persisted record and posting status.
- Update: the persisted record plus observed before/after changes. The corrected branch updates the original draft ID and preserves its earlier snapshot.

`RecordEvidence` in `packages/contracts/snapshots.ts` is the shared envelope. Populate `observation.record` when calling `captureStructuredCheckpoint`, or send it through `/api/visual-audit/observations` with action `structured`. Record only the actual response; do not mark a proposed write as succeeded. The integration accepts instrumented observations, rather than automatically watching every query a third-party agent makes.

`capturePdfRead` in `lib/pdf-evidence.ts` accepts real PDF bytes and a page/field search. It saves the original, extracts the selected text, renders the same page, and appends an evidence checkpoint. It rejects missing or ambiguous field matches. To inspect an arbitrary PDF independently, POST multipart fields `file`, optional `pageNumber` (1-based), and optional literal `quote` to `/api/visual-audit/pdf/inspect`. The response contains page text, match count, normalized bounds and a PNG preview; inspection alone does not add an investigation.

PDFs are limited to 20 MB and 100 pages. Text-based PDFs are supported; scanned/image-only PDFs need OCR and currently return a clear error. Page selection is supported by the adapter and inspection endpoint; the demo reads page 1 of each one-page source.

## Demo sources

`output/pdf/trust-bank-statement.pdf` and `trust-funding-instruction.pdf` are generated by `scripts/generate-trust-pdfs.py`. `/erp` opens these actual PDFs. The allocation worksheet remains an interactive browser form, accurately captured as a separate operation.

`/api/demo-ledger` uses parameterized SQLite operations: GET reads clients, POST inserts a draft, PATCH corrects an existing draft. SQLite lives beside the local investigation artifact directory, outside the repo. No financial posting is executed. Existing source snapshots are immutable observations even when the underlying draft changes.

## Verification

```powershell
python scripts/test-evidence-worker.py
pnpm typecheck
node scripts/check-mixed-ui.mjs
```

The UI check expects the local `PDF + Database Test` example and its corrected branch. It checks reads, saved change rendering, and original PDF access. The worker tests use an isolated temporary database and generated multipage PDFs, including empty/ambiguous evidence and rejected writes.
